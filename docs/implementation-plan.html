Implementation Plan

watch-cat 猫如厕行为干预系统 · 实施计划

版本 v1.0 日期 2026-07-07 依据 docs/product-design.md · docs/feasibility-review.html 执行人 1 名（开发 / 部署 / 运维 / 铲屎官四合一）

1总体安排

一、二期代码已就绪，实施重心在部署、标定与数据驱动的调优，不在开发。总周期约 8 周（其中大量时间是影子模式的被动观察，实际动手时间很少）；机器人阶段为条件立项，不在本周期内排期。

W1W2W3W4W5W6W7W8
P0 准备
M1 单点上线（影子）
M2 放声与调优
M3 组网扩容（影子/路）
M4 数据闭环开发
M5 机器人（条件立项）
橙色 = 影子模式（系统运行但不出声，人工审核期）；灰色 = 条件触发，不在本周期承诺。M3 的开始时间实际由热力图数据触发，此处按典型情况排在 W4–W6。

贯穿全程的两条纪律：① 任何一路摄像头放声之前必须先过影子模式审核（新增节点也不例外）；② 任何阈值调整必须回放回归视频集验证（M2 起建立）。

2P0 · 准备（第 1 周前半，约半天动手时间）

编号任务产出物 / 验收标准估时
P0-1硬件盘点：确定第一台旧手机（优先安卓、检查电池健康与鼓包迹象）、支架、原装充电器、常开主机硬件清单勾选完毕；电池异常的手机直接淘汰（安全红线）0.5h
P0-2录制吼声素材：3–5 段不同的你平时吼猫的录音（防脱敏储备），转 wavsounds/ 下 3–5 个 wav；手机外放试听音量足够0.5h
P0-3网络准备：路由器为手机绑定 DHCP 静态租约手机重启后 IP 不变0.5h
P0-4主机环境：克隆仓库、venv、pip install -r requirements.txt、跑测试pytest 17 个用例全部通过；YOLO 权重成功下载0.5h
P0-5建立《作案台账》：日期 / 时间 / 房间 / 位置 / 是否被干预（一张共享表格即可）台账模板就绪——这是 M3 布点和 M5 立项的数据源头，从今天起每次发现作案都记录0.5h

3M1 · 一期单点上线，影子模式运行（W1–W2）

3.1部署（1 天）

编号任务产出物 / 验收标准估时
M1-1手机装 IP Webcam：720p、关音频、开始服务；对准案发高发区固定支架主机浏览器能打开 http://手机IP:8080/video0.5h
M1-2手机装 Termux（F-Droid 版）：pkg install python mpv，部署 phone_sound_server.py 与吼声 wav浏览器访问 http://手机IP:8765/play，手机播出吼声1h
M1-3稳定性设置：两个 App 关电池优化、Termux 开唤醒锁、常插电、屏幕最暗；案发房间放小夜灯锁屏 30 分钟后视频流与放声服务仍可访问0.5h
M1-4主机配置：config.yaml 填入两个地址，确认 alert.enabled: false（影子模式，当前默认值）配置加载无报错0.2h
M1-5区域标定：calibrate_zone.py 画猫砂盆白名单；食盆若在画面内画 ignore 区标定窗口叠加显示区域正确0.3h
M1-6试运行：--show 模式观察半小时，确认状态流转（moving → stationary → scratching）符合直觉猫走动不误判静止；断 Wi-Fi 重连正常（现场拔一次电源验证）0.5h

3.2影子观察期（5–10 天，每天 10 分钟）

  • 每日回看 events/living_room/，在台账上逐条标注：真前兆 / 误报（写明原因：玩耍、舔毛、埋食物…）/ 漏报（地板有屎但无事件）。
  • 按误报原因调参：玩耍误报 → 调高 scratch_motion_threshold；埋食物误报 → 补画 ignore 区；漏报 → 调低阈值或 scratch_min_seconds。
  • 把有代表性的命中/误报片段另存为回归视频集（tests/regression/），此后每次调参用 --source 片段.mp4 回放全集。
晋级门槛 G1影子模式 → 放声

连续 5 天误报 < 1 次/天，且期间出现过 ≥ 2 次被正确捕获的真前兆。未达标则继续调参观察，不设截止日期强行放声——猫在系统被证明可靠前一声都不该听到。

4M2 · 放声与调优（W3–W4）

编号任务产出物 / 验收标准类型
M2-1开发：干预烈度阶梯（先轻"咳"声，10s 内行为未停再升级吼声）+ 每日触发上限单测覆盖阶梯与上限逻辑；配置项文档化开发 0.5d
M2-2开发：多段吼声随机播放（用 P0-2 的素材库）alert 支持声音列表；phone_sound_server 支持多文件开发 0.5d
M2-3alert.enabled: true，第一周仅启用轻提示音级别观察猫对轻声的反应，记入台账部署
M2-4升级到吼声级别；记录首次成功干预（触发 → 猫回猫砂盆）的完整录像标志性产出：首个端到端成功案例部署
M2-5开发：Bark/Server酱推送（触发时附快照）+ systemd 守护 + 每日心跳杀进程后自动拉起；手机收到推送开发 1d
M2-6运维例行化：每日摸手机温度、看心跳；每周核对台账与事件日志《运维清单》进入日常运维
验收门槛 G2一期验收

端到端延迟 ≤ 3s（录像时间戳核对）；干预成功率 > 80%（触发后 2 分钟内进猫砂盆区）；误报维持 < 1 次/天。同时观察台账：它开始换房间作案了吗？——这是 M3 的发令枪。

5M3 · 二期组网扩容（数据触发，典型 W4–W6）

触发条件：台账/热力图显示某个新房间发生 ≥ 2 次作案。扩容是标准化 SOP，每个新房间重复一遍，代码零改动：

编号任务说明估时
M3-1新节点部署复用 M1-1 ~ M1-5 清单（安卓机全流程；iPhone 只做推流，放声由外接音箱/邻近安卓机承担）2h/台
M3-2新路影子标定新增 cameras[] 条目暂不参与放声，影子跑 2–3 天；画质噪点差异用分路阈值覆盖（cameras[].behavior）单独调3d 观察
M3-3组网联调演练①跨房间冷却：人为让猫穿过两路视野，确认只吼一次；②故障隔离：拔掉一台手机电源，确认其他路不受影响、恢复后自动重连；③放声路由：每路触发时吼声来自本房间1h
M3-4主机容量核查全部路数上线后 CPU 占用 < 50%（超过则调大 interval 或降 imgsz）0.2h
晋级门槛 G3每路独立过关

每个新节点各自满足 G1 标准后才在该路放声。组网不改变纪律：新眼睛也要先学会不冤枉猫。

6M4 · 数据闭环（W6–W8）

编号任务产出物 / 验收标准估时
M4-1事件库与网页面板：SQLite 落库 + Flask 面板（各房间事件流、快照回看）手机浏览器可回看任意事件2d
M4-2热力图自动化：作案时间 × 房间分布图，替代人工台账面板展示；台账退役1d
M4-3干预成功率自动统计（触发后 2 分钟内是否进入猫砂盆区）面板展示成功率/误报率周趋势——脱敏的预警指标1d
M4-4存储滚动清理（events/ 保留最近 N GB）+ 摄像头被挡/移位检测告警磁盘占用封顶；遮挡 10 分钟内收到推送1d
M4-5规划项收尾：区域坐标归一化存储、无猫时段噪声底自动标定、10Hz 运动量重采样换机/换分辨率不再需要重标定与手工调阈值2d
验收门槛 G4二期总验收（也是项目主目标）

连续 30 天统计：地板作案次数较基线下降 ≥ 80%；节点可用性 > 95%；干预成功率无持续下滑（脱敏未发生）。达标后系统转入纯运维状态。

7M5 · 移动机器人（条件立项，独立项目周期 1–3 月）

立项门槛 G5三个条件同时满足才启动

① 热力图积累 ≥ 1–2 个月数据（决定巡逻时段与路线先验）；② 二期已稳定通过 G4；③ 数据证明仍存在固定布控无法覆盖的死角作案。若多点布控已解决问题，机器人不立项——它是兴趣驱动的可选章节，不是必需品。

阶段内容关键验收周期
R1-a平台采购（RoboMaster EP）+ SDK 打通：遥控、取流、放声手动遥控下完成一次"发现猫→靠近→放声"1–2 周
R1-b驯化期：机器人静止共处 → 缓慢移动 → 短距跟随，观察猫应激反应猫在机器人 2m 内正常进食/休息；出现持续应激则暂停并回退1–2 周
R1-c视觉伺服跟随：PID 保持 1.5–2.5m 距离；复用全部感知代码（猫静止则机器人静止）客厅范围 10 分钟跟随不丢失、不碰撞2–3 周
R1-d避屎防线一/二落地：事件坐标 → 污染禁区（人工确认清理后解除）；只从侧前方接近、不横穿猫身后模拟污染区（贴纸标记）测试：机器人 100% 绕行1 周
R2热区巡逻：按热力图在高危时段自动巡逻高发点饭后/清晨时段自动出勤、其余趴窝充电2–3 周
R3（远期）激光雷达 SLAM + 自动回充 + 视觉识屎数据集另行立项评审—

8回滚与应急预案

触发情形动作恢复条件
放声后误报明显伤猫（躲藏、应激、不敢进该房间）立即 alert.enabled: false 退回影子模式找到误报根因、回归集验证后，从轻提示音重新爬梯
调参后命中率下降git 回滚 config，回放回归视频集定位回归集全绿
某节点反复掉线/手机发烫异常该路下线（注释掉 cameras 条目即可），不影响其余房间更换设备后按 M3 SOP 重新上线
猫对吼声脱敏（成功率持续下滑）切换未用过的录音素材；启用推送+远程真人对讲补强成功率回升；长期靠 M4-3 指标预警
机器人引发持续应激机器人停用，退回多点固定布控（系统仍完整可用）驯化重新开始或放弃 M5
始终并行的治本线：实施期间同步排查猫砂盆卫生/数量/位置与砂的质地；若作案是近期突发，先约兽医排除肠胃与泌尿问题。任何一周若治本线有改善（如换砂后作案骤降），优先固化治本成果，系统退居保险角色。
