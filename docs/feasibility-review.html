1结论摘要

系统目标：在猫做出「拉屎前兆」（原地扒地 → 蹲姿）的 2–3 秒内，从案发房间的设备播放主人吼声，利用其既有条件反射将其劝回猫砂盆。三阶段总体判定如下：

一期 · 单手机定点 可行 代码已实现 全部依赖成熟组件（YOLO 预训练 + 帧差分 + HTTP），无需训练模型。17 个单元测试通过。成本 ≈ ¥50。
二期 · 多手机组网 可行 代码已实现 与一期同构，扩容 = 配置加条目。星型拓扑集中推理，4 路约占主机 0.5 个 CPU 核，容量余量大。
终极形态 · 移动机器人 有条件可行 设计阶段 R1 反应式跟随基于成品平台（RoboMaster EP）可落地；避障是成熟问题，避屎依赖三层防线设计（见 §4.3），视觉识屎为长期任务。

可测性设计：状态机与配置层是纯 Python、零依赖，与 IO 层（OpenCV / YOLO / HTTP）严格分离——不装任何重依赖即可跑全部 17 个单测；状态机按时间戳窗口而非帧数驱动，这是 §4.1 帧率异构的基础。

3关键链路延迟预算

干预必须发生在「扒地开始之后、开拉之前」。猫从扒地到进入排便通常有 5–15 秒，预算如下（从第一爪扒地起算）：

检测周期 ≤0.4s

合计 ≈ 2.7s ± 0.5s，对 5–15s 的行为窗口余量充足

4异常场景分析

4.1设备异构：iPhone / Android / 分辨率差异

架构已把异构限制在最小面：手机不参与计算，只是视频源。剩余的差异逐项分析：

差异维度影响对策状态
分辨率不同大部分算法不受影响关键阈值均按比例设计：静止容差 = 0.3×框宽，蹲姿 = 高宽比；YOLO 统一 letterbox 缩放到 imgsz。天然分辨率无关已实现
画质噪点 / 压缩伪影唯一分辨率敏感项：帧差运动量 scratch_motion_threshold，老手机噪点会抬高底噪导致误报每路摄像头可独立覆盖行为阈值（cameras[].behavior）；配合影子模式逐路标定已实现
同上（自动化）手工逐路调参繁琐无猫时段自动测量该路噪声底，阈值 = 底噪 + 固定余量规划
帧率不同（15 vs 30 fps）状态机不受影响（按时间戳窗口，非帧数）帧差幅度随帧间隔略变 → 规划固定 10Hz 重采样后再算运动量，彻底与帧率解耦规划
换机 / 换分辨率后区域失效猫砂盆多边形以像素存储，分辨率一变即错位区域坐标改为 0–1 归一化存储，加载时按实际分辨率还原规划
iPhone 生态限制iOS 无 Termux、无常驻后台：放声服务做不了；推流 App（如 IP Camera Lite）必须保持前台iPhone 降级为「只当眼睛、不当嘴」：推流用 RTSP App + 引导式访问防锁屏；该房间的放声由另一台安卓机或 ¥20 音箱（接主机蓝牙/有线）承担。结论：安卓优先，iPhone 可用但角色受限已论证

4.2识别的快与准：避免"误杀"伤害猫

先算代价的不对称性：漏报的代价是地板上多一坨（可清理）；误报的代价是猫无辜挨吼——反复误吼会造成焦虑、让吼声信号脱敏，甚至让它把"被吼"与错误的场景关联（比如在窗边晒太阳被吼）。因此设计原则定为宁漏勿错（Precision First），所有机制围绕这一点：

已实现多证据门控

触发必须同时满足：YOLO 确认是猫（人/狗/扫地机不触发）＋ 身体静止 2.5s ＋ 框内高运动量持续 1.5s；可选再叠加蹲姿（trigger_on: both）。猫砂盆/食盆白名单区域直接豁免，45 秒全局冷却封顶骚扰频率。

已实现影子模式分级上线

第 1 周 alert.enabled: false：系统完整运行、只记录不出声；人工回看 events/ 逐条标注真/误报并调阈值。达到「误报 < 1 次/天」的验收线后，第 2 周先放轻提示音，第 3 周才上吼声。猫在系统被证明可靠之前，一声都不会听到。

规划干预烈度阶梯

先播一声轻"咳"，10 秒内行为未停止再升级为吼声。即便发生残余误报，猫听到的也只是轻声——把误报伤害从"挨吼"降级为"可忽略"。

规划效果度量闭环 + 每日上限

触发后 2 分钟内猫进入猫砂盆区域 = 干预成功，自动统计成功率与误报率，用数据而非感觉判断系统是否在变好；每日触发上限（如 10 次）作为极端情况的硬保险丝。

精度天花板与升级路径：规则法（帧差 + 几何比例）的优势是零训练、可解释、纯 Python 可测；若影子模式数据显示某类场景（如激烈玩耍）始终无法用阈值区分，events/ 里积累的自家猫标注片段正好是训练集——可微调一个轻量二分类器（扒地 / 非扒地）或引入动物姿态估计。先用规则法收集数据，数据反过来决定要不要上模型，避免过早投入训练成本。

4.3机器人：自动避障，以及"绝不能压到屎"

避障是成熟问题——扫地机器人行业已解决，照抄传感器组合即可，风险在工程量而非可行性：速度上限 + 前向 ToF 反应式急停（R1 级），升级到激光雷达代价地图与虚拟墙（R3 级），碰撞条作最后兜底。

避屎才是真正的难点，因为屎是小尺寸、低对比度目标，纯视觉识别很难可靠（iRobot 为了给 j7 的避屎功能背书，专门训练了数千张宠物粪便照片）。本设计不把宝押在视觉上，而是三层防线，且前两层不依赖任何识别能力：

防线一事件驱动的污染区（本系统的独特优势）

这套系统的本职就是盯着猫拉屎——如果干预失败，系统精确知道屎在哪：触发事件的坐标即污染坐标。该位置自动标记为禁区，机器人绕行，直到人工在面板上确认"已清理"才解除。历史案发热力图上的高发点则常设为慢速谨慎区。

防线二行为策略：不走可能有屎的路

屎出现在猫屁股后方 → 机器人永远从侧前方接近，绝不横穿猫的身后区域；始终保持 ≥1.5m 距离；凡是"触发过事件且猫已离开、尚未人工确认"的区域一律不驶入。原则：不确定干不干净的地方就不进去。

防线三视觉识别兜底（长期任务）

前向摄像头跑小目标检测作为最后一道保险。需要自建数据集（含仿真样本），列为 R3 阶段任务。在它成熟之前，防线一 + 二已足以让 R1 级机器人安全上线——这是"避屎"不阻塞机器人立项的关键论证。

此外机器人还有一个一二期都没有的风险：观察者效应——被机器跟着的猫行为会变（应激、躲床底、换更隐蔽的地点作案）。对策为 1–2 周驯化期（静止共处 → 缓慢移动 → 跟随）加速度/噪音上限，并保留随时退回"多点固定布控"的能力。

5测试与验收策略

  • 单元测试（现状）：17 个用例覆盖状态机全部状态迁移（含"睡觉不触发""离场复位"等边界）、配置归一化、全局冷却、影子模式。核心逻辑层零重依赖，CI 秒级可跑。
  • 集成测试（缺口 → 规划）：main.py 原生支持视频文件输入；影子模式期间把真实的命中/误报片段沉淀为回归视频集，每次调阈值后回放全集，防止"修好一个误报、弄坏三个命中"。这是本项目最有价值的测试资产。
  • 分级上线：影子模式（只记录）→ 轻提示音 → 吼声，每级有量化晋级条件。

7总体结论

一、二期可行且代码已就绪：无自训模型、无自研协议、无非成熟依赖，最大的工程风险（设备异构、误报伤猫）分别被"集中推理 + 比例阈值 + 每路覆盖"和"影子模式分级上线"结构性化解。建议立即按部署清单启动一期，影子模式跑满一周再放声。

终极形态机器人建议在二期热力图数据积累 1–2 个月后立项：热力图直接决定巡逻策略与污染区先验，且届时感知代码已在多路实战中打磨成熟。R1 级（成品平台 + 反应式跟随 + 防线一/二避屎）为第一个可交付里程碑；纯视觉识屎不设为上线前提。

最后重申系统边界：本系统治标（第一时间抓现行），猫砂盆卫生/数量/位置与兽医检查治本，两者并行才是完整方案。
