# watch-cat 产品设计文档

> 目标: 在猫做出「拉屎前兆」(原地扒地 → 蹲姿) 的第一时间, 自动播放主人的吼声,
> 把它劝回猫砂盆。

## 已确定的建设路线

| 阶段 | 形态 | 状态 |
|---|---|---|
| **一期** | 一台旧手机盯住案发高发区 | ✅ 代码已实现 |
| **二期** | 多台旧手机多房间组网, 全屋布控 | ✅ 代码已实现 (加配置即用) |
| **终极形态** | 移动机器人跟踪 | 📋 设计就绪, 待立项 |

## 0. 核心洞察与对策

| 观察到的事实 | 产品对策 |
|---|---|
| 拉屎前有固定动作序列: 先扒地、后蹲姿 | 行为状态机识别前兆, 抢在蹲下前干预 |
| 对主人吼声有条件反射, 一吼就回猫砂盆 | 播放主人吼声录音, 而不是蜂鸣/超声波 |
| **被吼多了会学精, 换地方作案** | 加一台旧手机 = 堵住一个新房间, 边际成本趋近于零 |
| 事后惩罚无效, 只有"现行"时制止有效 | 系统 7x24 在线, 永远第一时间抓现行 |
| 吼声必须"来自现场"才有威慑力 | 手机既当摄像头又当音箱, 吼声就近发出 |

旧手机路线的妙处: 一台旧手机自带**摄像头 + Wi-Fi + 扬声器 + 电池 (兼UPS)**,
恰好就是一个完整的监控节点, 而它的采购成本是零。猫和你的攻防战里,
它每开辟一个新据点, 你翻出一台旧手机就地反制。

## 一期: 单手机定点布控 (已实现)

### 1.1 产品形态

一台旧手机对准案发高发区推视频流; 家里任一台电脑做主机跑检测;
触发时主机回调**同一台手机**播放吼声 —— 声音从案发现场发出。

```
旧手机 (案发房间)                     主机 (家里任一台电脑)
┌────────────────────┐   Wi-Fi     ┌──────────────────────────┐
│ IP Webcam 推视频流  │ ──────────> │ YOLO 猫检测               │
│                    │             │  → 行为状态机 (扒地/蹲姿)  │
│ Termux 放声服务     │ <────────── │  → 警报调度 (冷却 45s)     │
│  (播放你的吼声)     │  HTTP 触发  │  → 事件录像 + 日志         │
└────────────────────┘             └──────────────────────────┘
```

### 1.2 功能清单

| 功能 | 状态 |
|---|---|
| 猫检测 (YOLO 预训练, 免训练) | ✅ |
| 扒地/蹲姿行为状态机 | ✅ |
| 吼声路由到手机播放 (主机兜底) | ✅ |
| 全局冷却防轰炸 | ✅ |
| 猫砂盆白名单 / 食盆忽略区 | ✅ |
| 断流自动重连 (手机 Wi-Fi 掉线是常态) | ✅ |
| 事件录像回溯 (前 8s + 后 5s) | ✅ |
| 手机推送通知 (Bark/Server酱) | 🔲 增强项 |
| 夜视 (猫常凌晨作案) | 🔲 增强项, 见 1.4 |
| 作案热力图统计 | 🔲 增强项, 为二期布点提供数据 |

### 1.3 一期硬件清单 (成本 ≈ ¥50)

| 硬件 | 参考价 | 说明 |
|---|---|---|
| 旧安卓手机 | ¥0 (已有) | 摄像头+音箱二合一节点 |
| 手机支架 | ¥20 | 固定俯拍案发区, 避免被猫拱倒 |
| 充电器+线 | ¥0–30 | 常插电, 手机电池顺便当 UPS |
| (主机) 家里任一台电脑 | 已有 | 需常开; 也可以后换成树莓派/NAS |

### 1.4 已知短板与对策

- **夜视**: 手机摄像头没有红外。对策: 案发房间留一盏小夜灯 (¥10),
  或该房间换用带红外的 USB 摄像头接主机。猫不怕微光, 不影响"作案"。
- **手机发热/掉线**: 720p 推流功耗不高; 关屏推流 + 忽略电池优化 +
  路由器绑定固定 IP, 代码侧已做断流自动重连。
- **主机常开**: 检测跑在主机, 手机只推流。主机睡眠 = 系统失效,
  记得关掉自动睡眠。

### 1.5 一期软件清单

| 软件 | 跑在哪 | 用途 |
|---|---|---|
| IP Webcam (App) | 手机 | 视频推流 (http://IP:8080/video) |
| Termux + python + mpv | 手机 | 放声服务 `tools/phone_sound_server.py` |
| Python 3.9+ / ultralytics / OpenCV | 主机 | 检测与行为识别 (本仓库) |
| ffmpeg | 主机 | 吼声录音转 wav |

### 1.6 一期验收标准

- 猫在监控区扒地 ≤ 2 秒内手机发出吼声, 猫返回猫砂盆
- 连续一周误报 ≤ 1 次/天, 监控区内漏报 0 次
- **人工记录它转移到了哪些新地点** → 作案热力图, 指导二期布点顺序

## 二期: 多手机组网 (代码已支持, 加配置即扩容)

### 2.1 产品形态

每个案发房间放一台旧手机, 全部由同一台主机集中检测和调度。
架构与一期完全相同, 只是节点变多 —— **扩容 = config.yaml 加三行**:

```yaml
cameras:
  - name: living_room
    source: "http://192.168.1.101:8080/video"
    alert_url: "http://192.168.1.101:8765/play"
  - name: bedroom                                # ← 猫转移阵地, 加一台
    source: "http://192.168.1.102:8080/video"
    alert_url: "http://192.168.1.102:8765/play"
```

### 2.2 关键技术设计 (已实现)

1. **星型拓扑, 集中推理**: 手机只推流不算题, 检测集中在主机 ——
   旧手机性能参差不齐, 不能指望它们跑模型; 主机一颗 CPU 轮询多路流,
   yolov8n 每路每秒 2–3 次检测足够 (行为持续数秒, 不需要每帧都检)。
2. **就近放声**: 每路摄像头绑定自己的 alert_url, 哪个房间触发,
   哪个房间的手机吼。放声服务不可达时主机本地兜底并记日志。
3. **全局冷却**: 家里只有一只猫。猫从客厅晃到卧室, 两路先后触发,
   只吼一次 (45 秒全局冷却), 避免"到处都在吼"让猫脱敏。
4. **断流即重连**: 每路采集是独立线程, 只保留最新帧 (顺便消掉推流延迟),
   某台手机掉线不影响其他房间。
5. **独立区域标定**: 每路有自己的猫砂盆白名单/食盆忽略区,
   `tools/calibrate_zone.py --camera bedroom` 逐房间标定。

### 2.3 二期硬件清单 (每加一个房间 ≈ ¥20–50)

| 硬件 | 参考价 | 说明 |
|---|---|---|
| 旧手机 ×N | ¥0 | 不够可收二手 (~¥100/台, 能装安卓 7+ 即可) |
| 支架 ×N | ¥20 | |
| (可选) 二手充电器若干 | ¥10/个 | |
| 主机升级 (可选) | ¥0–650 | 3–4 路以内家用电脑无压力; 想省电换树莓派 5 |

**主机容量估算**: yolov8n@640 在普通桌面 CPU 上约 30–60ms/次。
4 路 × 每路 2 次/秒 = 8 次/秒 ≈ 0.5 核, 富余很大。
超过 6 路再考虑 `imgsz: 480` 或调大 `interval`。

### 2.4 二期增强路线图

| 增强 | 价值 | 实现 |
|---|---|---|
| 手机推送通知 | 不在家也知道它想作案, 附快照 | Bark/Server酱 HTTP 调用, 挂在触发点 |
| 网页面板 | 手机上回看各房间事件、热力图 | Flask + SQLite 读 events/ 目录 |
| 作案统计 | 时间/地点分布 → 优化布点和巡逻时段 | 事件日志聚合 |
| 声音多样化 | 防脱敏: 随机播放几段不同的吼声 | alert 支持声音列表随机选 |

> 防脱敏是真问题: 如果录音一成不变、且吼完没有后续 (你不在家),
> 猫可能学会"这个声音没有后果"。对策: 多段录音随机放 + 推送通知让你
> 远程补一句真人语音 (IP Webcam 支持双向对讲的版本可以直接喊话)。

### 2.5 二期验收标准

- 全部已知案发房间覆盖, 任意房间扒地 ≤ 2 秒触发本房间吼声
- 猫跨房间移动不被重复轰炸 (全局冷却生效)
- 单台手机掉线不影响其他房间, 且恢复后自动重连
- 一个月内地板作案次数下降 80% 以上 (以事件日志为准)

## 终极形态: 移动机器人跟踪

二期的多点布控总有死角 (床底、阳台、猫爬架后面), 猫也可能专挑死角。
终极形态: 一台带摄像头和喇叭的轮式机器人, 保持 1.5–2.5 米"礼貌距离"
跟随猫, 随时准备吼它。

### 3.1 必须正视的三个风险

1. **观察者效应**: 会动的机器跟着猫, 猫的行为会变 —— 可能吓得不敢作案
   (歪打正着), 也可能应激躲床底, 在更隐蔽处作案。需要 1–2 周驯化期:
   机器人先静止共处 → 缓慢移动 → 跟随。
2. **续航**: 全天跟随不现实。对策: 用一、二期积累的作案热力图,
   只在高危时段巡逻 (饭后 15–30 分钟、清晨), 其余时间趴窝充电。
3. **室内导航是硬骨头**: 避障、门槛、拖鞋、数据线… 全自主导航要
   激光雷达 + SLAM, 工程量是前面全部之和的数倍。

### 3.2 实现路线 (按难度递增, 每级都可独立使用)

| 级别 | 能力 | 技术 |
|---|---|---|
| R1 反应式跟随 | 视野内跟着猫, 丢失就地旋转搜索 | 视觉伺服 PID 控制轮速 + ToF 避障, 无需建图 |
| R2 热区巡逻 | 按热力图在作案点之间定时巡逻 | 预录路径点 + 里程计 |
| R3 全屋自主 | 建图、导航、自动回充、全屋找猫 | 激光雷达 + ROS2 SLAM/Nav2 |

关键复用: **猫静止时机器人也静止** —— 拉屎前兆恰好发生在猫静止后,
所以帧差分行为识别与一、二期完全复用; 二期的多节点调度经验
(MQTT 化后) 直接变成"机器人 + 固定节点"混合编队: 固定手机发现猫,
机器人赶过去接管跟踪。

## 5. 治本提醒

本系统是行为矫正工具, 若猫是**突然**开始乱拉, 优先排查: 猫砂盆卫生、
盆的数量 (猫数+1) 和位置、砂的质地气味、以及肠胃/泌尿疾病 (先看兽医)。
系统的干预 + 环境的改善双管齐下, 才能真正让它回到猫砂盆。
