# watch-cat 产品设计文档

> 目标: 在猫做出「拉屎前兆」(原地扒地 → 蹲姿) 的第一时间, 自动播放主人的吼声,
> 把它劝回猫砂盆。分两期建设: 一期定点布控, 二期扩大覆盖 / 移动跟踪。

## 0. 核心洞察与对策

| 观察到的事实 | 产品对策 |
|---|---|
| 拉屎前有固定动作序列: 先扒地、后蹲姿 | 行为状态机识别前兆, 抢在蹲下前干预 |
| 对主人吼声有条件反射, 一吼就回猫砂盆 | 播放主人吼声录音, 而不是蜂鸣/超声波 |
| **被吼多了会学精, 换地方作案** | 覆盖范围必须能扩展 —— 这是二期的立项依据 |
| 事后惩罚无效, 只有"现行"时制止有效 | 系统 7x24 在线, 永远第一时间抓现行 |

猫的「学精」是一场攻防战: 你堵住一个点, 它换一个点。终局有两种打法:

- **A. 多点布控**: 摄像头/云台逐步铺满它可能作案的房间 —— 成本低、稳定、无死角
- **B. 移动跟踪**: 一台机器人跟着猫走 —— 一台设备全屋覆盖, 但工程难度高一个数量级

二期两条路线都给出设计, 建议先 A 后 B: A 方案两周能落地, B 方案是长期项目。

## 一期: 定点布控 (已实现代码)

### 1.1 产品形态

一个摄像头对准当前的「案发高发区」, 主机上跑检测程序, 触发时音箱播放吼声。

```
┌──────────┐   USB/RTSP   ┌─────────────────────────┐
│ 摄像头    │ ───────────> │ 主机 (电脑/树莓派)        │
│ (对准案发区)│             │  YOLO猫检测 → 行为状态机  │
└──────────┘              │  → 播放吼声 + 保存录像    │
                          └───────────┬─────────────┘
                                      │ 3.5mm/USB
                                 ┌────▼────┐
                                 │  音箱    │ "喂!!!"
                                 └─────────┘
```

### 1.2 功能清单

| 功能 | 状态 | 说明 |
|---|---|---|
| 猫检测 | ✅ 已实现 | YOLO 预训练模型, 无需自己训练 |
| 扒地/蹲姿识别 | ✅ 已实现 | 静止 + 框内高运动量 = 扒地; 高宽比骤降 = 蹲姿 |
| 吼声播放 (带冷却) | ✅ 已实现 | 换成主人录音, 45 秒冷却防轰炸 |
| 猫砂盆白名单区域 | ✅ 已实现 | 盆里扒砂不报警; 食盆区可设忽略 (埋食物动作会误报) |
| 事件录像回溯 | ✅ 已实现 | 触发前 8 秒 + 后 5 秒, 用于调阈值 |
| 手机推送通知 | 🔲 一期增强 | 触发时推送快照到手机 (Bark / Server酱 / Telegram) |
| 夜视 | 🔲 一期增强 | 猫常在凌晨作案, 需要红外摄像头 + 补光 |
| 事件统计报表 | 🔲 一期增强 | 作案时间/地点分布, 为二期布点提供数据 |

### 1.5 一期验收标准

- 猫在监控区扒地 ≤ 2 秒内播放吼声, 猫返回猫砂盆
- 连续一周误报 ≤ 1 次/天 (通过 events/ 录像回看确认)
- 漏报 0 次 (监控区内的作案全部被抓现行)
- **同时收集数据**: 每次它换新地点作案, 人工记录位置 → 形成"作案热力图", 指导二期布点

## 二期: 扩大覆盖与移动跟踪

一期上线后猫必然把作案点转移到监控区外, 二期解决覆盖问题。

### 2.A 方案 A: 云台跟踪 + 多点布控 (推荐先做)

**产品形态**: 摄像头装在二轴舵机云台上, 猫走到哪, 镜头转到哪 ——
「摄像头装在移动物体上」的最小实现: 位置固定, 视角移动。
一台云台覆盖一整个房间; 高发房间各放一台, 由一台主机统一调度。

```
房间1: 云台摄像头 ─┐                ┌─ 触发 → 就近音箱播放吼声
房间2: 云台摄像头 ─┼─ MQTT/RTSP ──> │ 主机: 多路检测 + 跟踪调度
房间3: 固定摄像头 ─┘                └─ 事件库 + 手机推送 + 网页回看
```

**关键技术设计**

1. **视觉伺服跟踪**: YOLO 检出猫框 → 计算框中心与画面中心的偏差 →
   PID 控制器输出 pan/tilt 舵机角速度, 把猫始终"锁"在画面中央。
   检测 5–10 Hz, 控制环 20–30 Hz (帧间用轻量跟踪器插值, 如 ultralytics
   自带的 ByteTrack)。
2. **静止即停转 (关键!)**: 行为状态机靠帧间差分识别"扒地", 前提是画面静止。
   所以云台策略是: **猫移动时转动跟随, 猫一静止云台立即锁死** ——
   而拉屎前兆恰恰发生在猫静止之后, 因此行为识别逻辑与一期完全复用, 不用改。
3. **多机协同**: 每台云台是一个独立节点, 通过 MQTT 上报「猫在/不在、状态、
   事件」; 主机做全局裁决 (同一时刻只有一个节点该报警) 并统一冷却时间,
   避免猫穿过两个房间被连吼两次。
4. **接力跟踪**: 猫离开房间 1 视野 → 节点 1 上报"丢失" → 主机通知相邻节点
   进入"搜索模式" (云台缓慢扫描) → 谁先检到猫谁接管。

**方案 A 硬件清单 (每个房间一套, 约 ¥1000/套)**

| 硬件 | 参考价 | 说明 |
|---|---|---|
| 树莓派 5 (4GB) | ¥450 | 每节点独立推理, 或只推流由主机集中推理 |
| 摄像头模块 3 NoIR + 补光 | ¥250 | |
| 二轴云台支架 + MG996R 舵机 ×2 | ¥80 | 金属齿轮款, 塑料齿轮 SG90 易磨损 |
| PCA9685 舵机驱动板 | ¥25 | I2C 接树莓派, 16 路 PWM |
| 小音箱 | ¥50 | 每房间就近出声 |
| 电源/线材/外壳 | ¥120 | |
| (主机) 旧电脑或 NAS | 已有 | 跑 MQTT broker + 事件库 + 网页面板 |

*省钱替代: 直接买支持 ONVIF PTZ 协议的消费级云台监控摄像头 (¥150–300/台),
用 ONVIF 指令控制转动, 免去舵机 DIY; 缺点是转动速度和控制精度不如自建。*

### 2.B 方案 B: 移动机器人跟踪 (你设想的终极形态)

**产品形态**: 带摄像头和喇叭的轮式机器人, 在屋里跟着猫, 保持 1.5–2.5 米
"礼貌距离", 随时准备吼它。

**先泼三盆冷水 (设计必须正视的风险)**

1. **观察者效应**: 一个会动的机器跟着猫, 猫的行为会变 —— 可能被吓得不敢
   作案 (歪打正着?), 也可能应激、躲床底, 反而在更隐蔽处作案。需要 1–2 周
   "机器人静止共处 → 缓慢移动 → 跟随"的驯化期。
2. **续航与充电**: 全天跟随不现实。对策: 结合一期的作案热力图, 只在高危
   时段巡逻 (猫多在饭后 15–30 分钟、清晨排便), 其余时间趴窝充电。
3. **室内导航是硬骨头**: 避障、门槛、拖鞋、数据线…全自主导航需要激光雷达
   + SLAM (ROS2 + Nav2), 工程量是前面所有功能之和的数倍。

**实现路线 (按难度递增, 每级都可用)**

| 级别 | 能力 | 技术 |
|---|---|---|
| B1 反应式跟随 | 视野内跟着猫, 丢了就地打转搜索 | 视觉伺服 PID 控制轮速 + ToF 避障, 无需建图 |
| B2 热区巡逻 | 按热力图在几个作案点之间定时巡逻 | 预录路径点 + 简单里程计 |
| B3 全屋自主 | 建图、导航、自动回充、全屋找猫 | 激光雷达 + ROS2 SLAM/Nav2 |

**距离保持**: 由猫框像素高度估算距离 (标定一次: 你家猫框高 X 像素 ≈ Y 米),
或加一颗 ToF 激光测距。太近后退, 太远跟进, PID 控制。

**行为识别复用**: 与云台同理 —— 猫静止时机器人也静止, 帧差分依然有效。

**方案 B 硬件: 两条采购路线**

*路线 1: 成品平台二次开发 (推荐, ≈ ¥3500–4500)*

| 硬件 | 参考价 | 说明 |
|---|---|---|
| 大疆 RoboMaster EP | ¥3500 | 官方 Python SDK, 自带相机/喇叭/麦轮底盘, B1 级最快落地 |
| 或 Enabot EBO X | ¥4000+ | 本身就是宠物陪伴机器人, 但 SDK 开放度有限 |

*路线 2: 树莓派 DIY (≈ ¥1500–2500, 可玩性高)*

| 硬件 | 参考价 | 说明 |
|---|---|---|
| 树莓派 5 (8GB) | ¥650 | 机器人大脑 |
| 麦克纳姆轮/履带底盘套件 (含电机) | ¥300–600 | 履带过门槛能力强, 麦轮灵活安静 |
| TB6612 电机驱动 ×2 | ¥30 | 比 L298N 效率高、发热小 |
| 摄像头模块 3 NoIR + 云台 (复用 2.A) | ¥330 | 车身 + 云台两级跟踪, 车不动镜头动 |
| VL53L1X ToF 测距 ×3 (前/左/右) | ¥60 | B1 级避障够用 |
| (B3) LD19 / RPLIDAR C1 激光雷达 | ¥400–600 | 上 SLAM 才需要 |
| 3S 锂电池组 + 稳压模块 | ¥150 | 2–3 小时续航 |
| 小功率喇叭 + 功放板 | ¥40 | |

**方案 B 软件清单**

| 软件 | 用途 |
|---|---|
| 一期 + 2.A 全部软件 | 感知与行为识别复用 |
| robomaster SDK (路线1) | 底盘/云台/喇叭控制 |
| gpiozero + pigpio (路线2) | 电机 PWM 控制 |
| (B3) ROS 2 Humble + slam_toolbox + Nav2 | 建图导航回充 |

### 2.C 两方案对比与建议

| | A. 云台+多点 | B. 移动机器人 |
|---|---|---|
| 单房间成本 | ≈¥1000 | — |
| 全屋 (3 房间) 成本 | ≈¥3000 | ¥3500 (成品) / ¥2000 (DIY) |
| 工程难度 | ★★ (两周) | ★★★★★ (数月) |
| 可靠性 | 高, 无移动部件卡死风险 | 中, 导航/续航/驯化都是变数 |
| 对猫的干扰 | 无 | 有, 需驯化期 |
| 好玩程度 | ★★ | ★★★★★ |

**建议路径**: 一期 → 2.A 云台版 (顺手把 PID 跟踪、MQTT 多节点这些 B 也要用
的模块练出来) → 猫如果还能找到布控死角、或者你就是想造机器人 → 2.B。
2.A 的感知/伺服/协同代码在 2.B 里 100% 复用, 不存在推倒重来。

## 4. 治本提醒

本系统是行为矫正工具, 若猫是**突然**开始乱拉, 优先排查: 猫砂盆卫生、
盆的数量 (猫数+1) 和位置、砂的质地气味、以及肠胃/泌尿疾病 (先看兽医)。
系统的干预 + 环境的改善双管齐下, 才能真正让它回到猫砂盆。
